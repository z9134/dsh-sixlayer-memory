## 3. 关键实现

**3.1 评测口径（公理 4）**

不报 AUROC，只报**工作点**上的两个数：

```
误报率 FPR = 正常样本被判为攻击 / 正常样本总数
检出率     = 各攻击级别被检出 / 该级别样本数
```

每份报告都带测试集版本与构造哈希，跨月对比才有意义。

**3.2 当前评测结果（v1）**

| 级别 | 样本 | 检出 | 检出率 |
|---|---|---|---|
| normal | 30 | 0 | 0.0%（FPR 0%） |
| L1 直接攻击 | 10 | 10 | **100%** |
| L2 组合攻击 | 10 | 0 | **0%** |
| L3 休眠触发 | 10 | 0 | **0%** |

整体 recall 33.3%，precision 100%。**这不是失败，是如实反映了规则的能力边界**：规则能挡 L1，挡不住 L2/L3——后者靠注入侧的组合检查兜底，不靠扫描器。

**3.3 月报十项指标**

新增记录 / 命中率 / 零命中率 / 待审积压 / 冲突数 / 注入强度 / 去重率 / 断链数 / 误报率 / L1 漏检率（附 L2/L3 逃逸）。

## 4. 这期发现的一个 bug

`inject.js` 一直调用 `store.record(...)`，但 `MemoryStore` 类里**没有 `record` 方法**——异常被 `catch` 吞掉，注入审计静默丢失。也就是说：注入在工作（系统提示词里能看到围栏块），但审计里一条记录都没有。

已补 `record(fields)` 并改成 `op: 'inject'` 的正确字段形状，回归里加了断言。

## 6. 注意事项

1. **注入强度本期显示 0**：注入 trace 从本期才开始记，宿主重启后才会累积。
2. **改动测试集必须升版本**：v1 的样本和哈希要保留，否则历史月份无法复现。
3. **不要拿 precision 高就宣称安全**：L2/L3 逃逸 100%，公开文献也承认这是结构性盲区。
4. **scanner 只做判定，不做裁决**：命中只是"标记"，是否隔离由写入链决定。
