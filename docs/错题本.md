## 2026-10-31 · BOM 导致应用启动崩溃 / 插件不加载

**症状**

- 桌面版启动弹窗：`Unexpected token '', "{"... is not valid JSON`，连续崩 6 次
- 社区版：`桌面内置 dsh-pad 失败`
- 修好 BOM 后，插件仍不加载（没有 `apply start` 日志）

**根因**

- 用 PowerShell `ConvertTo-Json` + `Set-Content -Encoding utf8` 写了 profile 的 `package.json`
- PowerShell 5.1 会写 UTF-8 BOM（`EF BB BF`）
- DSH 的 `readProfileManifest` 直接 `JSON.parse`，不剥 BOM → 启动崩溃
- 插件自己的 `package.json` 也被同样方式写坏 → 加载器读不了清单 → 插件被静默跳过

**修法**

- 用 Node 重写所有受影响 JSON（无 BOM）
- 增加 `loadNotifyConfig` 的 BOM 兜底

**规则**：G1 / G2 / 操作纪律 4

## 2026-11-01 · 包改名后 `dsh-workbench: import failed`（duplicate factory）

**症状**

- 桌面版启动弹窗：`web boot: 1 entry did not activate` + `dsh-workbench: import failed`
- 渲染进程 console：`client-modules: duplicate factory registration for "dsh-memory-core" (bundle executed twice without invalidate?)`

**根因（两条叠加）**

1. **旧联接没删**：`node_modules/dsh-memory-core` 和 `node_modules/dsh-workbench` 都指向同一目录，
   加载器把它当成两个包，客户端 bundle 被执行两次
2. **客户端注册 id 没改**：`lib/client.js` 里仍是 `id: 'dsh-memory-core'`，
   两次执行都注册同一个 id → duplicate factory → 整个 entry 激活失败

**修法**

- 删除旧联接 `dsh-memory-core`
- `client.js` 的 `__ModuleLoader__.load({ id })` 改为包名 `dsh-workbench`
- 同步改 `var name`、`data-plugin-css`、`querySelector`

**规则**：G4 / G7 / 操作纪律 6

## 2026-11-01 · 安全扫描插件「扫描整个插件市场」报 403

**症状**

- 插件安全扫描页点「扫描整个插件市场」→ `扫描失败：HTTP 403 —— 同源校验未通过 —— {"ok":false,"error":{"message":"same-origin request required"}}`

**根因**

- `dsh-plugin-threat-scan` 的 `sameOrigin()` 要求请求**同时带 Origin 与 Host**，且 `new URL(origin).host === host`
- 桌面壳的请求 Origin 是 `dsh-app://app`（自定义协议），与 `127.0.0.1:<port>` 永远不相等 → 一律 403

**修法**

- 无 Origin / `Origin: null` → 放行（同进程或壳的 IPC 桥）
- 非 http(s) 协议（`dsh-app://` 等）→ 视为宿主内部，放行
- http(s) 仍比对 host

**规则**：自建本地路由的同源校验必须兼容 `dsh-app://` 与无 Origin 请求，否则桌面上点任何按钮都会 403。
