## 3. 关键实现

**3.1 三级兜底**

```
SMTP 失败 → 飞书 webhook → 本地 outbox
```

`sendReport()` 永远不抛错，返回 `{ok, channel, attempts}`，每级失败原因都记下来。**报告先落盘**，通知失败不影响报告。

**3.2 SMTP**

手写 AUTH LOGIN + 465 端口 TLS，不引 nodemailer（保持零依赖）。邮件头用 UTF-8 Base64 编码，中文主题不会乱码。

**3.3 季度建议的判定**

| 条件 | 建议 |
|---|---|
| 断链数 > 0 | P0：立即修，停止写入 |
| 待审 > 20 | P1：集中审核或降低未验证来源写入 |
| FPR > 10% | P1：逐条看命中的 scanner，收紧误伤那条 |
| L1 检出率 < 90% | P1：检查 scanner 是否被误改 |
| L2/L3 = 0 | P2：结构性盲区，不要靠加规则硬扛 |
| 去重率 > 30% | P2：可能有重复写入源 |
| 命中率环比降 20% | P2：检查分词器与索引一致性 |

**3.4 凭据**

- 配置文件：`D:\001\CH002\dsh-memory-data\meta\smtp.json`
- ACL：`icacls /inheritance:r /grant:r <当前用户>:(R,W)`，其他用户不可读
- 报告、日志、返回体里都不出现授权码

## 6. 注意事项

1. 授权码等同于密码，泄露要立即在 QQ 邮箱里「删除授权码」。
2. 飞书 webhook 比邮箱授权码风险低，若 QQ SMTP 被运营商拦截，优先切飞书。
3. 季度单只出建议，**不自动改参数**；改完要跑固定测试集并记录回滚值。
4. 报告先落盘这条不能省——通知链路挂了，证据还在。
