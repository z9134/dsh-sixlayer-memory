## 一、先回答你问的两个事实问题

### 1. 工作台跟 QQ 官方插件，通道通了吗？

**通了，链路是：**

```
QQ 用户 ──> @tencent-connect/dsh-qqbot（腾讯官方，已装、已配 AppID/Secret）
              │  inject: ['agents']
              ▼
        ctx.agents → agent 会话（默认 preset）
              │  工具来自全局注册表
              ▼
        工作台的 27 个工具（mem_search / mem_write / mem_associate / mem_resume …）
```

证据：

- 插件已安装并加载，注册了 `qqbot_send_file` 工具（我这边工具列表里能看到）
- 它通过 `ctx.agents` 开会话，没有做工具白名单过滤
- 工作台的记忆注入走 `systemPrompt.context`，**所有会话**（含 QQ 会话）都会带记忆快照

**但有一个前提没验证**：QQ 里发一条消息，agent 是否真的调得到 `mem_*`。
这取决于 agent preset（如果 preset 限定了工具子集，就可能看不到）。
→ 这需要一次实测，见「六、验证步骤」。

### 2. 你在 QQ 上聊出的情绪，有情绪数据库吗？

**现在没有。** 必须说清楚：

| 现状 | 说明 |
|---|---|
| 有「记录级情绪」 | 每条**写进记忆库的记录**在写入时算一次 affect_label（B1 做的） |
| 没有「聊天级情绪」 | QQ 里的对话不会自动写进记忆库，也就不会产生情绪标签 |
| 没有情绪事件表 | 没有按时间/会话记录「你什么时候说了什么情绪的话」 |
| 没有分析报告 | 只有记忆库的情绪分布，没有按天/周的情绪分析 |

一句话：**情绪能力有，但只覆盖“被记住的事”，不覆盖“你平时说的话”。**

## 二、要建什么：情绪观察

### 2.1 目标

把你在 QQ 上（以及本地）说的话，按**情绪事件**记下来，产出可读的分析：

- 今天/本周情绪分布、负面占比
- 情绪波动的时间段规律
- 高频触发词（因什么高兴/烦）
- 极端情绪提醒（可选，主动在 QQ 里提一句）

### 2.2 数据模型（新表 `affect_events`）

```sql
CREATE TABLE affect_events (
  event_id     TEXT PRIMARY KEY,
  session_id   TEXT,            -- 来源会话（QQ/本地）
  source       TEXT,            -- qq / local / manual
  occurred_at  TEXT NOT NULL,   -- 消息时间
  label        TEXT NOT NULL,   -- neutral/positive/negative/urgent
  valence      REAL,            -- -1..1
  arousal      REAL,            -- 0..1
  excerpt      TEXT,            -- ≤80 字摘要（脱敏后）
  excerpt_hash TEXT,            -- 去重与检索
  triggers     TEXT,            -- JSON：命中的词/句式
  created_at   TEXT NOT NULL
);
```

**隐私口径**：

- 只存 ≤80 字摘要（`redact` 过），**不存全文**
- S 级内容（凭证/隐私）不入此表
- 可一键关闭采集（配置 `affect.enabled`）
- 报告只给聚合，不导出原文

### 2.3 采集路径（按可行性排序）

| 方案 | 做法 | 风险 |
|---|---|---|
| **A. 事件订阅**（推荐） | 监听 DSH 的会话/agent 消息事件，对 user 消息调 `analyzeAffect`，写 `affect_events` | 需要确认 DSH 是否暴露该事件（半天验证） |
| B. QQ 插件适配 | 改官方插件，把消息转发给工作台的 API | 改第三方代码，升级会覆盖 |
| C. 工具约定 | 在系统提示里要求 agent 每轮调 `mem_capture_emotion` | 依赖模型自觉，不稳定 |
| D. 会话日志回放 | 定时解析 `~/.dsh/sessions/` | 事后、延迟、格式易变 |

**推荐 A，A 不可行再退 C+D 组合。**

### 2.4 分析层

- 工具：`mem_affect_report({ range: 'day'|'week'|'month', source? })`
- 面板：观测页新增「情绪」子块（分布 / 趋势 / 触发词 top）
- 报告：复用现有月报/季报管线，增加情绪章节
- QQ 命令：`/情绪` 返回今日摘要

### 2.5 分期

| 期 | 内容 | 验收 |
|---|---|---|
| 一期 | 事件表 + 采集（方案 A）+ `/情绪` 命令 + 今日摘要 | QQ 聊 10 句，观测页出现 10 条情绪事件 |
| 二期 | 周报分析：分布、时段、触发词、波动 | `mem_affect_report week` 输出完整分析 |
| 三期 | 主动提醒：连续负面/极端情绪时在 QQ 提一句 | 可配置阈值与开关 |

## 三、你现在看到的按钮，分别是干什么的

设置 → 工作台，9 个页签：

| 页签 | 作用 | 关键按钮 |
|---|---|---|
| **总览** | 记录数、待审、S 级、分层分布、最近操作 | 无 |
| **检索** | 手动搜记忆（FTS + 中文） | 搜索框 |
| **待审** | 非可信来源写入的审核队列 | 批准 / 拒绝 / 释放 |
| **交接** | 场景交接卡（last/projects/changes/next/blockers） | 读取某场景 |
| **派单** | 协作任务台账与状态机 | 查看状态 |
| **观测** | 近 24h 注入/召回 + 情绪分布 + 14 天趋势 | 无（纯展示） |
| **零件** | 内置零件 + 已装插件 + 零件库 | **安装 / 卸载**、搜索、分类 |
| **安全** | 插件安全扫描（融合 threat-scan） | **扫描已发现目标 / 扫描整个插件市场** |
| **审计** | 哈希链完整性 + 最近 trace | 深度体检 |

零件页的「安装」：确认后调官方 CLI 安装、登记 bundle、提示重启。
零件页的「卸载」：从 bundles 移除 + 卸载包，保护工作台自身与 `@deepseek-ai/*`。
安全页的「扫描」：调 threat-scan 的本地静态分析，不联网、不执行被扫代码。

## 一期落地记录（1.3.0）

- schema v8：新增表 `affect_events`（event_id / session_id / source / occurred_at / label / valence / arousal / excerpt / excerpt_hash / triggers / created_at）
- 采集路径：`~/.dsh/sessions/--…-dsh-qqbot-workspace--/session-<id>/session.v4.jsonl.zstd`
  - 多帧 zstd 按魔数切帧逐帧解压
  - 只收 `user/message` 且 `data.source.kind === 'user'`（runtime-context / time-context / skill-catalog 都是注入，跳过）
  - 摘要 ≤80 字、先过 redact；按 (session_id, excerpt_hash, occurred_at) 去重
- 词表扩展：难过 / 不开心 / 心情 / 烦 / 累 / 压力 / 焦虑 / 委屈 / 生气 / 崩溃；开心 / 高兴 / 爽 / 棒 / 期待 / 满意
- 工具：`mem_affect_report({range})`、`mem_affect_ingest({limit})`
- 面板：观测页新增「今日情绪事件（QQ 采集）」卡片 + 立即采集按钮
- 后台：每 10 分钟自动采集（config.affect.enabled=false 可关）
- 实测：本机 2 个 QQ 会话、7 条真实用户消息，其中「我现在心情有点小难过」正确标为 negative，触发词 难过/心情

## 二期：日报 / 周报（1.4.0）

- 报告落盘：`dsh-memory-data/reports/affect/<YYYY-MM-DD>-day.md`（周报 `-week.md`）
- 自动生成：启动时立即生成一次；之后每 6 小时生成日报；周一 9 点补周报
- 手动生成：`mem_affect_report({ range: "week", save: true })`
- 报告内容：分布、负面占比、高频触发词、时段条形图、一句结论

## 三期：情绪提醒（1.4.0）

两条通道，可分开关闭：

1. **注入提示**（config.affect.hint，默认开）
   近 N 小时（默认 3）负面/紧急 ≥ 阈值（默认 2）时，系统提示词的记忆快照多一行：
   > 情绪提示：近 3 小时负面/紧急消息 N 条。先安抚再解决，语气放慢，不追问细节。

2. **主动通知**（config.affect.notify，默认开）
   每 30 分钟检查一次；尖峰时走现有邮件/飞书通道发一封提醒；同一次尖峰 6 小时冷却（`meta.affect_last_notify`）。

关闭方式：

```yaml
affect:
  enabled: true
  hint: false       # 关注入提示
  notify: false     # 关主动通知
  hours: 3          # 窗口
  threshold: 2      # 负面条数阈值
```
