# 一期日志：工作台大插件（dsh-workbench）

日期：2026-11-01
版本：dsh-memory-core 0.11.0 → **dsh-workbench 1.0.0**
状态：核心改造完成，待重启验证 + QQ 端到端

## 这一期干了什么

### 1. 一个插件，两条线（目录重组）

```
dsh-memory-core/lib/
├─ index.js                 ← 组装入口（只留组装）
├─ client.js                ← 统一面板
├─ memory/                  ← 记忆线（20 个文件平移）
│  ├─ store.js / schema.js / inject.js / tools.js
│  ├─ policy.js / scanners.js / emotion.js / api.js
│  ├─ qq.js / qq-official.js / service.js / service-plugin.js
│  └─ …
└─ parts/                   ← 零件线
   └─ index.js              ← 零件契约 + compose 装配
```

- 包名改为 **`dsh-workbench`**，版本 **1.0.0**
- bundle patch 只插一行：`id: workbench`
- **工具名一个没改**（`mem_*` 继续可用），数据目录不变
- 迁移后 19 个测试套件全绿

### 2. 统一服务 `workbench`

```js
ctx.workbench.memory.recall(...)   // 记忆线
ctx.workbench.parts.list()         // 零件线
ctx.workbench.parts.compose({...})
```

- 同时注册 `memory` 别名，旧消费者不炸
- 仍是**独立插件行**（`workbench-service`），挂了不影响主插件

### 3. 续跑：`mem_resume`

新工具，解决「在 QQ 上接着说昨天的事」：

```
mem_resume({ scene? })
→ 未完成任务（现象/做法/验收）
→ 该场景的交接（last/projects/changes/next/blockers）
→ 相关记忆（按任务标题检索）
```

测试：p16 7 项（注册、任务、四件套、交接、结构化、无 scene、完成后不列）

### 4. 零件页签

- 面板新增「零件」tab，列出 5 个零件（名称/版本/用途）
- 对应 RPC 端点 `parts`
- 设置入口改名「工作台」（不再是「记忆底座」）
