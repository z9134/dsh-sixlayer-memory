# 方案：记忆底座服务化（独立一期）

- 日期：2026-10-31
- 定位：让**别的插件**通过 Cordis 服务调用记忆，而不是把插件装进记忆底座
- 与"装插件"的关系：**无关**。本方案不新增任何加载/安装能力

---

## 1. 目标与非目标

**目标**：记忆底座对外提供一个窄服务 `memory`，任何插件 `inject: ['memory']` 就能召回/写入/查状态。

**非目标**：
- ❌ 不做插件安装/加载（那是 DSH Loader 的事）
- ❌ 不暴露数据库、SQL、正文读写
- ❌ 不让消费者绕过写入链（闸门/分级/脱敏照旧）

## 2. 服务契约（v1，五个方法）

```js
ctx.memory = {
  apiVersion: 1,

  // 召回：只给指针，不给正文；S 级永不返回；未验证来源只给 id
  recall({ query, principal, scope: 'personal'|'group' = 'personal', topK = 5 }) -> {
    pointers: [{ record_id, layer, sad_level, created_at, summary? }],
    degraded?: true
  },

  // 写入：走完整写入链（信任判定 → 扫描 → 分级 → 去重 → 闸门）
  remember({ content, source, principal, projectId, tags }) -> {
    record_id, status, trust_level, sad_level
  },

  // 遗忘：只降层/归档，永不物理删除
  forget({ record_id, mode: 'archive'|'downgrade' = 'archive' }) -> { record_id, status },

  // 健康：给面板/监控用
  status() -> { records, active, pending, sLevel, audit, schemaVersion, authority },

  // 交接（可选）：多 agent 场景共用 §〇
  handoff: { read(scene), write({ scene, sections }) }
}
```

**契约纪律**：

| 纪律 | 原因 |
|---|---|
| 只回指针，不回正文 | 正文要走 `mem_read` 与审计 |
| S 级永不出现 | 凭证不能因为"别的插件要"就漏出去 |
| 未验证来源不给摘要 | 公理 3：只能当线索 |
| 写入必须走写入链 | 否则闸门形同虚设 |
| 失败返回 `{ degraded: true }` 或抛明确错误 | 消费方要能降级 |

## 3. 权限与身份

消费方调用时传 `principal`（如 `qq:123456`、`desktop:owner`），服务内部按 v3 的策略矩阵处理：

| 场景 | 读 | 写 | S 级 |
|---|---|---|---|
| 桌面本人 | 全部（S 需显式） | 是 | 需显式 |
| 私聊 trusted | A 级 | 是（可能待审） | 拒绝 |
| 群聊 | 只看群共享层 | 仅显式 remember | 拒绝 |

> 诚实说明：同一宿主进程内的插件是可信的，`principal` 由调用方声明；服务只做**策略执行**，不做身份伪造防护。跨进程/多用户的强身份要等宿主提供。

## 4. 生命周期与降级

- `apply()` 里 `ctx.provide('memory', service)`，卸载时自动移除。
- 名字冲突：先 `ctx.get('memory')` 探测；已存在则**跳过并告警**（可配置 `serviceName` 覆盖）。
- 库打不开（degraded）：服务照常提供，但方法返回 `{ degraded: true, reason }`，不抛异常。
- 消费方约定：`try { ctx.memory.recall(...) } catch {}`，没有记忆就照常回答。

| 文件 | 改动 |

**不动数据库**：不需要 schema 变更，不需要迁移。

## 6. 验收（行为级）

1. mock ctx 下 `apply()` 调用 `ctx.provide('memory', …)`，且 `apiVersion === 1`
2. `recall` 返回的指针里没有 `content` 字段；S 级记录不出现
3. 未验证来源的指针没有 `summary`
4. `remember` 写未验证来源 → 落待审（证明没绕过闸门）
5. `forget` 只改状态，记录仍在（不物理删除）
6. 服务不可用（降级）时方法返回 `{degraded:true}` 而不是抛错
7. 现有 9 个测试套件全部通过（无 schema 变更）

## 7. 风险与回滚

| 风险 | 处理 |
|---|---|
| 服务名 `memory` 与未来插件冲突 | 注册前探测 + `serviceName` 配置覆盖 |
| 跨插件可见性不确定（Cordis scope） | 用 mock + 一个真实消费者验证；不可见则退回 `ctx.provide` 到根作用域 |
| 消费方拿到服务后长期持有引用 | 服务只返回纯数据，不暴露 store |
| 契约以后要改 | `apiVersion` 版本门；不兼容改动升 2 |

**回滚**：删掉 `ctx.provide` 那几行即可，无数据变更。
