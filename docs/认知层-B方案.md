# 认知层（B 方案）设计与路线

## 目标

让记忆从「检索」变成「联想」：不只是"你问什么我找什么"，而是"由 A 想到 B"，
并且记得住"这件事让我高兴/难受/着急"。

## 三层

| 层 | 做什么 | 实现 |
|---|---|---|
| 情绪层 | 写入时给每条记忆打效价/唤醒度 | `lib/emotion.js`，规则词表，零依赖 |
| 重要性层 | 综合情绪强度 + 层级给出 0..1 初值，后续 beta 修正 | `initialImportance()` + `records.importance` |
| 联想层 | 标签、语义、情绪三路召回并加权合并 | `store.associate()` + `mem_associate` 工具 |

## 数据

schema v7，`records` 新增四列：

```
affect_label    neutral / positive / negative / urgent
affect_valence  -1..1
affect_arousal  0..1
importance      0..1（写入初值，beta 继续修正）
```

## 设计原则

1. **确定性**：规则算，不调模型。同样的文本永远得到同样的标签。
2. **可解释**：每条联想都给出理由（`标签:xxx` / `语义` / `同情绪:xxx`）。
3. **可纠正**：重要性不是死的，`mem_judge` 的 beta、`mem_review` 的审核都能改它。
4. **不越权**：情绪标签只影响排序和提示，不改变闸门、不绕过 S 级限制。

## 路线

- **B1（已完成）**：情绪标注 + 重要性初值 + `mem_associate` + 观测页情绪分布
- **B2（下一步）**：注入排序引入情绪加权——高唤醒的负面记忆优先浮出，避免"好了伤疤忘了疼"
- **B3（下一步）**：注入里带一行「关联」——当本轮上下文命中某条记忆时，顺带提示它关联的记忆
- **B4**：观测页加情绪趋势（按天/按标签），看"这个月是不是一直在救火"
- **B5**：与 dsh-context 的联合观测（取决于第 3 点怎么落地）

## 风险与对策

| 风险 | 对策 |
|---|---|
| 规则误判（反讽、否定句） | 词表保守；`mem_review` 可人工改标签；观测页看分布异常 |
| 情绪放大偏差（负面记忆过度权重） | 重要性上限 1.0；注入排序里情绪只占一部分权重，不是唯一因子 |
| 隐私 | 情绪标签跟随记忆，S 级仍不参与注入与联想正文 |

## 第 3 点（嵌入 dsh-context）现状

`dsh-context` host 只注册 `sessionProjections`，不暴露 service/RPC，客户端是自洽的 530KB bundle。
要真正把记忆卡片嵌进它的 Context 面板，只能 fork。当前先做「并排观测」，
fork 作为一个独立决策项，等 B 的其余部分稳定后再评估。
