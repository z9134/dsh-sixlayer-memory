# 认知层第二增量（B2 + B3）实施记录

日期：2026-10-31
版本：0.4.0 → 0.5.0
schema：v7（不变）

## B2：注入时的情绪加权

`lib/inject.js` 的 `selectSnapshot` 排序从

```
ORDER BY (alpha IS NULL), alpha DESC, created_at DESC
```

改为

```
rank_score = COALESCE(alpha, 0.5)
           + CASE WHEN affect_label IN ('negative','urgent')
                  THEN 0.15 * COALESCE(affect_arousal, 0) ELSE 0 END
ORDER BY (alpha IS NULL), rank_score DESC, created_at DESC
```

意图：**高唤醒的负面记忆优先浮出**——"好了伤疤忘了疼"的反面。
权重 0.15 是有意压低的：情绪只是排序因子，不能盖过 alpha 和组合限制。

## B3：注入里的关联提示

`Injector.text()` 在选出条目后，取**首条**的最强关联，追加一行：

```
> 关联：<record_id>（标签:xxx、语义）<摘要>
```

约束：

- 只加一行，且不超 `maxChars`
- 取不到关联就静默不加
- 联想查询在 `store.associate()` 里补了 `sad_level != 'S'` 过滤（**顺带修掉一个 S 级泄漏风险**）

## 怎么验证

`tools/p9.mjs`（5 项）：

- 负面高唤醒排在类似中性记录之前
- S 级不进注入池
- 注入文本带 `> 关联：` 行
- 关联正文不含 S 级内容

全量回归：p1 15、p2 13、p3 10、p4 12、p5 24、p6 17、write-chain 20、smoke 19、phase2 23、tools 24、p8 15、p9 5，全绿。

## 注意事项

1. **注入文本会多一行**：如果有强关联，系统提示词里的记忆快照会多出 `> 关联：` 行，属预期，不是格式错误。
2. **S 级过滤是这次顺带修的安全项**：之前标签/同情绪两路联想没有排除 S 级，虽然注入池本身排除 S，但联想行可能间接带出指针。现在两路都排除了。
3. **情绪加权只影响注入排序**，不影响检索结果，也不改 alpha/beta。
