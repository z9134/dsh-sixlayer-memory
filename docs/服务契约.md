# 记忆底座服务契约（v1）

> 给第三方插件作者：怎么在**不安装、不合并**的前提下，用上本机的记忆。

---

## 1. 它是什么

记忆底座在宿主里注册了一个 Cordis 服务 `memory`。任何插件声明依赖后即可调用：

```js
export const inject = ['memory']

export function apply(ctx) {
  const { pointers } = ctx.memory.recall({ query: '部署', principal: 'qq:123' })
  // pointers 只有 id / 层 / 级别 / 时间（和摘要），没有正文
}
```

**它不是插件加载器。** 它不能装别的插件，只提供"记忆"这一个能力。

## 2. 接口（apiVersion = 1）

### `recall({ query, principal, scope?, topK? })`

| 参数 | 说明 |
|---|---|
| `query` | 检索词（中文 bigram 分词） |
| `principal` | 调用方身份，如 `qq:123456` / `desktop:owner` |
| `scope` | `personal`（默认）/ `group`——v1 群聊一律返回空 |
| `topK` | 条数，默认 5 |

返回：

```js
{
  pointers: [
    { record_id, layer, sad_level, created_at, summary? } // 未验证来源没有 summary
  ]
}
```

**纪律**：只给指针。要正文请让用户确认后走 `mem_read` 或宿主工具，不在服务里给。

### `remember({ content, source, principal, projectId?, tags? })`

走完整写入链：信任判定 → 投毒扫描 → 分级 → 去重 → 闸门。

- `source` 是通道名：`user` / `web` / `plugin` / `mcp` …
- 非 `user` 来源默认 `unverified`，会进**待审**，不会立刻可召回
- 返回 `{ record_id, status, trust_level, sad_level, dedup, skipped }`

### `forget({ record_id, mode? })`

- `mode: 'archive'`（默认）→ 状态置 `archived`，不再被检索
- `mode: 'downgrade'` → 深度 +1，仍在库
- **永不物理删除**

### `status()`

```js
{ records, active, pending, sLevel, audit, schemaVersion, authority }
```

## 3. 三条不变量

1. **只回指针，不回正文**——正文永远要经过显式读取与审计。
2. **S 级永不出现**——凭证类记录不会因为"插件要"就漏出去。
3. **写入不绕过闸门**——未验证来源一定进待审。

## 4. 降级

库不可用、或服务没注册时：

```js
try {
  const r = ctx.memory?.recall({ query }) ?? { pointers: [] }
} catch {
  // 拿不到记忆就照常回答，不阻塞主流程
}
```

方法在降级时返回 `{ pointers: [], degraded: true, reason }`，**不抛异常**。

## 5. 冲突与改名

默认服务名 `memory`。如果已被其他插件占用，记忆底座会**跳过注册并告警**。

改名：

```yaml
- id: memory-core
  config:
    serviceName: memoryCore
```

## 6. 版本策略

- `apiVersion` 是整数；**加方法**不升版本，**改语义/删方法**升版本。
- v1 不含 `handoff`；多 agent 交接等有真实消费者再加，属于向后兼容的增量。

## 7. 谁在用它

目前没有第三方消费者。第一批预计是 IM 渠道插件（QQ / 飞书），用来"私聊能记、群聊不记"。
