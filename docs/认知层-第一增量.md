# 认知层第一增量（B1）实施记录

日期：2026-10-31
版本：0.3.0 → 0.4.0
schema：v6 → v7

## 干了什么

1. 新增 `lib/emotion.js`
   - 三组词表：正面 / 负面 / 紧急，命中计数
   - 标点信号：感叹号最多加 2 点唤醒
   - 输出 `{ label, valence, arousal, intensity }`
   - `initialImportance(affect, layer)`：0.35 基线 + 0.35 情绪 + 0.15 唤醒 + L2+ 层级加成

2. schema v7
   - `records` 增加 `affect_label / affect_valence / affect_arousal / importance`
   - 迁移幂等（先查 pragma 再加列）

3. 写入路径（`store.write`）
   - 写入时算一次情绪，落库
   - 重要性用情绪 + 层级给初值

4. 联想（`store.associate` + `mem_associate`）
   - 种子可以是 `record_id` 或一句话
   - 三路召回：标签重叠（权重 1）、语义 FTS（0.8）、同情绪（0.4）
   - 同一条被多路命中会累加权重，并合并理由
   - 输出按权重排序，每条带 `reasons` 数组，可解释

5. 观测页
   - 新增「情绪分布」卡片：中性/正面/负面/紧急各多少条

## 注意事项

1. **旧记录没有情绪标签**：25 条存量都是 `neutral`（写入时还没这功能）。要做回填的话，写个一次性脚本跑 `analyzeAffect(summary)` 更新即可，但会改动数据，先不做。
2. **迁移不可逆**：v7 只加列不删列，回退代码会报"库版本高于代码"。回退前先备份。
3. **词表是中文优先**：英文覆盖了常见词，但反讽、双重否定仍会误判——这是规则法的固有局限，靠 `mem_review` 人工纠正。
4. **联想不等于搜索**：`mem_search` 是"找匹配"，`mem_associate` 是"找相关"；后者会返回语义不完全匹配但标签/情绪相近的记忆，这是特性不是 bug。
