# B5：把「记忆」放进右侧栏（与 dsh-context 并排）

版本：0.10.0
日期：2026-11-01

## 背景

用户要把记忆底座和 dsh-context 的 Context 面板“放到一起”。
dsh-context 的 host 只注册 `sessionProjections`、不暴露 service/RPC，客户端是自洽的 530KB bundle，
**没有子 slot 可以往里塞卡片**——硬嵌入只能 fork，升级成本高。

## 做法

dsh-context 自己是通过这套席位注册右侧栏的：

```js
ctx.inject(['sidebarRightTabs'], (sub) => {
  sub.sidebarRightTabs.register({ id, kind, title })
  sub.slots.inject('sidebar.right.pane.tab', () => sub.slots.register({ name, key }, render))
  sub.slots.inject('sidebar.right.pane.tab.title', () => sub.slots.register({ name, key }, titleRender))
})
```

我们照抄同一套契约，注册一个自己的页签：

- `id/key = 'memory-core'`
- 标题「记忆」
- 内容复用已有的 `Panel`（总览/检索/待审/交接/派单/观测/审计）

效果：**右侧栏出现两个并排页签——「Context」（dsh-context）和「记忆」（我们）**，
不用 fork、不用改它一行代码，它升级也不受影响。

## 改动

1. `lib/client.js`
   - `apply()` 里新增 `ctx.inject(['sidebarRightTabs'], ...)` 注册页签
   - `Panel` 加连接守卫：没有 `connection.rpc` 时显示提示而不是崩
2. `package.json`
   - `dsh.client.inject` 增加 `@deepseek-ai/dsh-client-ui-sidebar-right`
3. 版本 0.10.0

## 验证方式

重启后打开右侧栏，应看到「Context」旁边多一个「记忆」页签；点开内容和设置页里的面板一致。

如果页签没出现：F12 → Console 看 `[dsh-memory-core]` 开头的警告（会写明是 register 失败还是
slot 注册失败），把那一行发回来即可定位。

## 与 fork 方案的关系

- 本方案：并排页签，**零维护成本**
- fork 方案：把记忆卡片嵌进 Context 面板内部，需要跟 dsh-context 的每次升级，收益是“同一屏”
- 结论：先用并排；除非确实需要同屏，否则不做 fork
