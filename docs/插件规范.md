# 插件规范（硬性规则）

> 这些规则不是建议，是**改完必须过 `preflight` 才能重启**的硬性检查。
> 每条都对应一次真实事故，见 [错题本](错题本.md)。

## 运行方式

```bash
node tools/preflight.mjs                       # 检查插件自身
node tools/preflight.mjs --profile <profile>   # 额外检查 profile 一致性
node tools/verify-all.mjs                      # preflight + 全部测试套件
```

**全过（PREFLIGHT OK）才允许重启。** 失败时按输出里的文件名修，不要带着失败重启。

---

## G1 · 文件编码：一律不得带 BOM

- 适用：`*.json / *.yml / *.yaml / *.js / *.mjs / *.md`
- 原因：DSH 用 `JSON.parse` 读 profile manifest，**不剥 BOM**；带 BOM 会让应用启动崩溃或插件被静默跳过。
- 禁止：PowerShell `Set-Content -Encoding utf8`、`ConvertTo-Json`、`Out-File -Encoding utf8`（PS 5.1 会写 BOM）
- 允许：Node `fs.writeFileSync(file, text, 'utf8')`；编辑工具的写入
- 修法：`node tools/strip-bom.mjs`（或 preflight 报哪个修哪个）

## G2 · JSON 必须可解析

- 所有 `.json` 用 `JSON.parse` 能过（注意 BOM 已被 G1 覆盖）
- `package.json` 字段：`name / version / type / main / exports / dsh.bundle.patch`
- 修法：改完立刻 `node -e "JSON.parse(fs.readFileSync(...))"`

## G3 · 包清单必须指向真实文件

- `main`、`exports.*`、`dsh.bundle.patch` 指向的路径都存在
- 重命名/移动文件后，必须同步改 `package.json`
- 事故：目录重组后 exports 还指向旧路径 → loader import failed

## G4 · 客户端 bundle 必须自包含，且 id 与包名一致

- `lib/client.js` **不能有 `import` 语句**（浏览器端没有模块解析）
- `window.__ModuleLoader__.load({ id: '<包名>' })` 里的 id 必须等于 `package.json` 的 `name`
- 事故：包名改 `dsh-workbench` 但 client 仍注册 `dsh-memory-core` → `duplicate factory registration` → `web boot: entry did not activate`

## G5 · 宿主模块的相对导入必须可解析

- `lib/index.js`、`lib/memory/tools.js`、`lib/memory/store.js`、`lib/parts/index.js`、`lib/memory/service-plugin.js` 里
  所有 `from './x.js'` / `from '../y.js'` 都能找到文件
- 移动文件后必须全量检查，不能只改主入口
- 事故：`parts.js` 移到 `parts/index.js` 后 `tools.js` 仍 `import './parts.js'`

## G6 · 工具注册表必须可构建且字段完整

- `buildRegistry()` 能跑通
- 每个工具都有 `name / description / parameters / output / execute`
- `package.json` 的 `dshx.contributes.tools` 数量与实际一致
- 事故：新增工具忘了登记 contributes，导致市场/面板少显示

## G7 · profile 联接唯一、bundles 无旧包名、patch 无重复 id

- `node_modules` 里同一插件**只能有一个联接**（改名后必须删旧的）
- `dsh.profile.bundles` 不能残留旧包名
- `cordis.patch.yml` 里同一条目的 `id` 不能重复
- 事故：`dsh-memory-core` 和 `dsh-workbench` 两个联接指向同一目录 → 客户端 bundle 执行两次 → 重复工厂注册 → 启动失败

## G8 · 库版本不得高于代码版本

- 打开库前先比 `meta.schema_version` 与 `SCHEMA_VERSION`
- 回退代码前必须先备份库；否则会进入降级（库版本高于代码）
- 事故：v7 库配 v6 代码，全部工具降级

---

## 操作纪律（不是自动检查，但必须遵守）

1. **改代码 ≠ 改配置**：改 `lib/*.js` 后必须重启应用（ESM 按 URL 缓存，热载不会重新 import）。
2. **一次改一批，跑一次 preflight**：不要改一行重启一次。
3. **重启前备份**：动 `cordis.patch.yml` / `package.json` 前先复制一份 `.bak-*`。
4. **不要用 PowerShell 写 JSON/YAML**（见 G1）。
5. **配置改动后立刻校验**：`JSON.parse` / YAML 结构 / BOM。
6. **新包名上线顺序**：建新联接 → 改 bundles → 改 patch → 删旧联接 → preflight → 重启。
7. **失败就回滚**：保留旧联接/旧 patch 备份，preflight 失败立即回退，不要连着重启。
