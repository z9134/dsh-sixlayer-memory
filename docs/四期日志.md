## 3. 关键实现

**3.1 注册方式（与现有插件一致）**

```js
slots.register({ name: 'settings.section', id: 'memory-core', order: 27, label: () => '记忆底座' }, ...)
```

**3.2 数据通道**

```
client ──rpc.call('/memory-core', endpoint, payload)──► host handler
```

| endpoint | 作用 | 是否写 |
|---|---|---|
| `status` | 记录数/待审/S 级/审计/分层 + 最近 5 条 trace | 否 |
| `search` | 检索（走 store.search，S 级默认不返回） | 否 |
| `read` | 读单条；S 级不传 `includeSensitive` 时只回元数据 + denied | 否 |
| `pending` | 待审与隔离区 | 否 |
| `review` | 批准 / 放行 / 拒绝 | **是**（唯一写操作） |
| `traces` | 最近 trace（回放入口） | 否 |

**3.3 安全边界**

- S 级正文默认不返回：`store.read` 在未显式授权时把 `content` 整个键去掉，并返回 `denied: true`。
- UI 没有"直接改库"的通道；审核走的是与工具层同一个 `store.review()`。
- 断链时顶部红条（`status.audit.ok === false`）。

## 6. 修复记录（2026-10-31 晚）

**现象**：面板能出现，但一加载就报 `transport failure for /memory-core/status: HTTP 405`。

**根因**：插件没有声明 `connection` 依赖。`connection.rpc.handle()` 内部要 `owner.webServer.register(route)`，拿不到服务时路由根本没注册；请求落到静态文件处理器，它对非 GET 一律返回 405。

**修复**：
- `lib/index.js` 的 `inject` 加上 `'connection'`；
- RPC 注册改用 `ctx.connection`（保留 `ctx.get` 兜底）。

**代价**：`connection` 是必需依赖，纯 headless 环境（没有 web 服务器）下插件不会加载。当前两个 profile 都是 web 服务，暂不受影响；如果以后要跑无头模式，把 UI 拆成独立插件行。

**顺带发现**：`dsh-plugin-vault` 有同样的隐患（`inject = ['tools']`，但用了 `ctx.get('connection')`），它的「下载隔离区」面板很可能也注册不上——需要时按同样方式修。

## 6. 注意事项

1. 面板只做四件事：看、搜、审、查。**不做**导入、改 authority、编辑记录——这些仍走工具，保证可回放。
2. 审核是唯一写操作，点「批准」会把信任升为 `trusted`，与工具层行为一致。
3. 视图数据是实时的，但没有自动轮询；切回「总览」会重新拉一次。
4. 如果浏览器缓存了旧 bundle，强制刷新一次（Ctrl+F5）。
